Loading and route selection

Unknown fields and invalid types are errors. Nunya collects independent errors using data-free diagnostics. Configure at least one route: a PostgreSQL-wire upstream, a native Spanner listener, or both. An upstream section requires a valid top-level listener. A native-only configuration may omit both the upstream section and top-level listener.

nunya policy check --config nunya.toml
nunya serve --config nunya.toml

Credentials and environment variables

The loader reads only the following two secret environment variables as configuration fallbacks. It does not expand environment references inside TOML strings.

KeyType / defaultMeaning and validation
NUNYA_ROOT_KEYenvironment string; no defaultUsed only when root_key_file is absent. Supply 64 hexadecimal characters. Root key input accepts exactly 32 raw bytes, or trimmed UTF-8 text containing 64 hexadecimal characters.
NUNYA_UPSTREAM_PASSWORDenvironment string; no defaultUsed only when upstream.password_file is absent. Must decode as UTF-8. Trailing CR and LF characters are removed.

A configured secret file wins over its environment variable. An unreadable or invalid file produces an error; it does not fall back to the environment. Root key material is held in zeroizing storage. Keep keys, session state, password files and SCRAM verifiers private.

umask 077
nunya key generate > root.key
printf '%s\n' 'your-upstream-password' > upstream.password

The command writes a fresh 32-byte key as lowercase hex. The password above is a placeholder to replace locally, never a shipped credential.

Inbound TLS keys

The same inbound certificate and key serve the configured routes. Under [tls], both paths are required. The loader reads PEM certificate and private-key material and constructs a server configuration; missing, malformed or incompatible material fails validation. Client certificates are not required by this TLS configuration; agents authenticate with session credentials.

KeyType / defaultMeaning and validation
cert_filenonempty path; required in tlsPEM server certificate chain.
key_filenonempty path; required in tlsPEM private key.
[tls]
cert_file = "server-chain.pem"
key_file = "server-key.pem"

Omit the entire TLS section only with an explicit trusted-local plaintext setting. Adding a TLS section still requires valid certificate material even if plaintext is allowed.

Config-managed principal keys

Use repeated [[standing]] tables. No principals are configured by default. They authenticate only to the management API, never to database ports. They cannot be edited, disabled or re-credentialed through the API; assign grants through the API before acquiring sessions. This table has no grant syntax.

KeyType / defaultMeaning and validation
namestring; requiredUnique, nonempty principal name. Names beginning task: are reserved and refused.
verifierstring; requiredValid PostgreSQL SCRAM-SHA-256 verifier: positive decimal iterations, base64 salt, and 32-byte decoded stored/server keys.
nunya standing hash

Enter one password line on standard input. Set name and verifier in a repeated [[standing]] table, using the generated verifier verbatim.

Native Spanner keys

Under [spanner_native], unknown keys are errors. Both routes share policy, root key, durable session store, config-managed principals and inbound TLS.

KeyType / defaultMeaning and validation
route_idstring; "spanner-native"Route ID: 1-63 ASCII characters; start with a lowercase letter or digit, then lowercase letters, digits, dot, underscore or hyphen. The two routes must have distinct IDs. Changing the database behind an ID breaks token continuity.
listensocket-address string; requiredAgent gRPC listener address.
databasestring; requiredExactly projects/PROJECT/instances/INSTANCE/databases/DATABASE with all three identifiers nonempty.
emulator_endpointstring; omittedMust start with the HTTP scheme. Explicit trusted plaintext emulator route, without Google credentials; takes precedence over endpoint when both are present.
endpointstring; default Google Spanner HTTPS serviceMust start with the HTTPS scheme. Selects a trusted production endpoint when no emulator endpoint is configured.
snapshot_refresh_mspositive integer; 30000Native snapshot refresh interval. This is separate from the top-level PostgreSQL interval.
[spanner_native]
route_id = "spanner-native"
listen = "127.0.0.1:6433"
database = "projects/my-project/instances/my-instance/databases/my-database"
emulator_endpoint = "http://127.0.0.1:9010"
snapshot_refresh_ms = 30000

The production default endpoint is the HTTPS service at spanner.googleapis.com. Production upstreams use Google credentials. For a native-only file omit the upstream section and top-level listen key; still supply policy, root key, state directory and either TLS or explicit plaintext permission. Native-only operation includes the admin listener. Admin reload, Unix SIGHUP and optional policy file watching update every serving route together.

Management API configuration

[management] is optional; when absent there is no TCP management listener. JSON requests use HTTP/1.1. This listener is separate from admin_listen. Its only keys are listen, tls, and repeated admin entries. Unknown keys are errors.

listen is a required socket-address string, with no default. It cannot equal the PostgreSQL, native Spanner or private administration listener address. TLS is required off loopback, including wildcard addresses. Optional tls requires nonempty cert_file and key_file paths resolved against the config file; valid matching PEM material is required even on loopback.

[management]
listen = "10.0.0.5:6481"
tls = { cert_file = "management-chain.pem", key_file = "management-key.pem" }

[[management.admin]] entries default to empty. Each entry requires a unique nonempty name, which must not equal a [[standing]] name and cannot be used by API-created principals, and valid PostgreSQL SCRAM-SHA-256 verifier, with no extra keys. Generate a verifier with nunya standing hash. These administrator credentials authenticate only to management. Unix also exposes state_dir/nunya.sock, owned by the service user with mode 0600; it grants administrator authority for bootstrap. Windows has no socket: configure an administrator entry for initial access.

Token lifetimes

Tokens belong to an access session scope. Reconnects and renewals preserve that scope; a replacement session needs fresh tokens. Optional [session] accepts only max_lifetime and idle_timeout.

[session]
max_lifetime = "8h"
idle_timeout = "1h"

max_lifetime defaults to 8h, with an inclusive range of 1 minute through 30 days. idle_timeout defaults to 1h; it must be at least 1 minute and no greater than max_lifetime, or exactly "off" to disable idle expiry. A shorter maximum may require explicitly reducing the idle timeout too. Durations are positive decimal integers followed by one lowercase s, m, h or d, with no spaces or fractions and no unsigned 64-bit seconds overflow.

To shorten exposure, lower these two settings or request a shorter session with --ttl 15m on session acquisition. An omitted TTL uses max_lifetime; requests above it are refused. Renewal revalidates principal and grants and extends idle time only within the absolute limit. When a session expires or is revoked, its authenticated connections lose access.
