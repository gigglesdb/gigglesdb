Loading and route selection

Unknown fields and invalid types are errors. Nunya collects independent errors using data-free diagnostics. Configure at least one route: a PostgreSQL-wire upstream, a native Spanner listener, or both. An upstream section requires a valid top-level listener. A native-only configuration may omit both the upstream section and top-level listener.

nunya policy check --config nunya.toml
nunya serve --config nunya.toml

Each route may select its own policy. Relative policy paths resolve against the configuration file's directory. The optional top-level key is the fallback. A configured route without either path fails startup with upstream.policy: required path missing (no service-level policy) or spanner_native.policy: required path missing (no service-level policy).

policy = "policy.toml"          # optional fallback for routes without their own

[upstream]
policy = "pg-policy.toml"       # PostgreSQL route validates only against the PG catalog
# ...

[spanner_native]
policy = "spanner-policy.toml"  # native Spanner route validates only against its catalog
# ...

This fragment omits the remaining route settings. To opt into the old single-policy behavior, name the same file on both routes, directly or through the fallback. Each route validates only its own policy against its own catalog, including during nunya policy check; columns need exist only on the route that protects them. Files with the same canonical path are one reload unit. See shared and per-route state and independent reloads and status.

Credentials and environment variables

The loader reads only the following two secret environment variables as configuration fallbacks. It does not expand environment references inside TOML strings.

KeyType / defaultMeaning and validation
NUNYA_ROOT_KEYenvironment string; no defaultUsed only when root_key_file is absent. Supply 64 hexadecimal characters. Root key input accepts exactly 32 raw bytes, or trimmed UTF-8 text containing 64 hexadecimal characters.
NUNYA_UPSTREAM_PASSWORDenvironment string; no defaultUsed only when upstream.password_file is absent. Must decode as UTF-8. Trailing CR and LF characters are removed.

A configured secret file wins over its environment variable. An unreadable or invalid file produces an error; it does not fall back to the environment. Root key material is held in zeroizing storage. Keep keys, session state, password files and SCRAM verifiers private.

umask 077
nunya key generate > root.key
printf '%s\n' 'your-upstream-password' > upstream.password

The command writes a fresh 32-byte key as lowercase hex. The password above is a placeholder to replace locally, never a shipped credential.

Inbound TLS keys

The same inbound certificate and key serve the configured routes. Under [tls], both paths are required. The loader reads PEM certificate and private-key material and constructs a server configuration; missing, malformed or incompatible material fails validation. Client certificates are not required by this TLS configuration; agents authenticate with session credentials.

KeyType / defaultMeaning and validation
cert_filenonempty path; required in tlsPEM server certificate chain.
key_filenonempty path; required in tlsPEM private key.
[tls]
cert_file = "server-chain.pem"
key_file = "server-key.pem"

Omit the entire TLS section only with an explicit trusted-local plaintext setting. Adding a TLS section still requires valid certificate material even if plaintext is allowed.

Config-managed principal keys

Use repeated [[standing]] tables. No principals are configured by default. They authenticate only to the management API, never to database ports. They cannot be edited, disabled or re-credentialed through the API; assign grants through the API before acquiring sessions. This table has no grant syntax.

KeyType / defaultMeaning and validation
namestring; requiredUnique, nonempty principal name. Names beginning task: are reserved and refused.
verifierstring; requiredValid PostgreSQL SCRAM-SHA-256 verifier: positive decimal iterations, base64 salt, and 32-byte decoded stored/server keys.
nunya standing hash

Enter one password line on standard input. Set name and verifier in a repeated [[standing]] table, using the generated verifier verbatim.

Native Spanner keys

Under [spanner_native], unknown keys are errors. Both routes share the root key, durable session store, config-managed principals and inbound TLS. Each route may select its own policy; all policy files must name the same read-log sink.

KeyType / defaultMeaning and validation
route_idstring; "spanner-native"Route ID: 1-63 ASCII characters; start with a lowercase letter or digit, then lowercase letters, digits, dot, underscore or hyphen. The two routes must have distinct IDs. Changing the database behind an ID breaks token continuity.
listensocket-address string; requiredAgent gRPC listener address.
databasestring; requiredExactly projects/PROJECT/instances/INSTANCE/databases/DATABASE with all three identifiers nonempty.
emulator_endpointstring; omittedMust start with the HTTP scheme. Explicit trusted plaintext emulator route, without Google credentials; takes precedence over endpoint when both are present.
endpointstring; default Google Spanner HTTPS serviceMust start with the HTTPS scheme. Selects a trusted production endpoint when no emulator endpoint is configured.
snapshot_refresh_mspositive integer; 30000Native snapshot refresh interval. This is separate from the top-level PostgreSQL interval.
policynonempty path; omittedPolicy TOML path for this native Spanner route, relative to the configuration file's directory. Falls back to the top-level policy; one must be supplied.
[spanner_native]
route_id = "spanner-native"
listen = "127.0.0.1:6433"
database = "projects/my-project/instances/my-instance/databases/my-database"
emulator_endpoint = "http://127.0.0.1:9010"
snapshot_refresh_ms = 30000

The production default endpoint is the HTTPS service at spanner.googleapis.com. Production upstreams use Google credentials. For a native-only file omit the upstream section and top-level listen key; still supply a route-level or fallback policy, root key, state directory and either TLS or explicit plaintext permission. Native-only operation includes the admin listener. Admin reload and Unix SIGHUP attempt each distinct policy file independently; optional policy watching watches each file separately. Routes sharing one file reload together, validated against all of their catalogs. A rejected edit leaves only that file's routes on their last good policy.

Management API configuration

[management] is optional; when absent there is no TCP management listener. JSON requests use HTTP/1.1. This listener is separate from admin_listen. Its only keys are listen, tls, and repeated admin entries. Unknown keys are errors.

listen is a required socket-address string, with no default. It cannot equal the PostgreSQL, native Spanner or private administration listener address. TLS is required off loopback, including wildcard addresses. Optional tls requires nonempty cert_file and key_file paths resolved against the config file; valid matching PEM material is required even on loopback.

[management]
listen = "10.0.0.5:6481"
tls = { cert_file = "management-chain.pem", key_file = "management-key.pem" }

[[management.admin]] entries default to empty. Each entry requires a unique nonempty name, which must not equal a [[standing]] name and cannot be used by API-created principals, and valid PostgreSQL SCRAM-SHA-256 verifier, with no extra keys. Generate a verifier with nunya standing hash. These administrator credentials authenticate only to management. On Unix, nunya serve always exposes state_dir/nunya.sock, even without [management], owned by the service user with mode 0600; it grants administrator authority for bootstrap. Windows has no socket: configure an administrator entry for initial access.

Token lifetimes

Tokens belong to an access session scope. Reconnects and renewals preserve that scope; a replacement session needs fresh tokens. Optional [session] accepts only max_lifetime and idle_timeout.

[session]
max_lifetime = "8h"
idle_timeout = "1h"

max_lifetime defaults to 8h, with an inclusive range of 1 minute through 30 days. idle_timeout defaults to 1h; it must be at least 1 minute and no greater than max_lifetime, or exactly "off" to disable idle expiry. A shorter maximum may require explicitly reducing the idle timeout too. Durations are positive decimal integers followed by one lowercase s, m, h or d, with no spaces or fractions and no unsigned 64-bit seconds overflow.

To shorten exposure, lower these two settings or request a shorter session with --ttl 15m on session acquisition. An omitted TTL uses max_lifetime; requests above it are refused. Renewal revalidates principal and grants and extends idle time only within the absolute limit. When a session expires or is revoked, its authenticated connections lose access.

Reloadable and restart-only settings

Admin POST /reload, Unix SIGHUP and file-watch triggers re-read the config with the strict startup loader, then attempt policy reloads independently. See reload procedures and status.

Reloadable

SettingEffect
[tls] cert_file, key_file, and file contentsFiles are re-read on every reload, even when the config text is unchanged. Replacing files in place rotates the certificate for new PostgreSQL and native Spanner handshakes. Open connections keep theirs.
max_connectionsRaising applies to the next PostgreSQL connection. Lowering closes nothing; new connections are refused until the open count is below the new limit.
schemas, search_pathA new PostgreSQL catalog snapshot is captured and the current policy validated before applying. Schemas named in search_path are always captured too; an empty schemas captures all non-system schemas. On failure nothing applies. Open PostgreSQL connections keep their original search path for both Nunya name resolution and the upstream session. New connections use the new path.
snapshot_refresh_ms, [spanner_native] snapshot_refresh_msThe refresh timer restarts with the new interval.
[[standing]]Added entries become usable. A changed verifier replaces the credential; the principal, its sessions and scopes are unchanged. Removing an entry disables the principal through the same path as POST /v1/principals/{id}/disable: in-flight work is cancelled, result release stops, and its connections close. Clients get NY011; on native Spanner an RPC in flight gets NY011 and later RPCs get the uniform NY003. New logins are refused. Names used by API principals are refused.
[session] max_lifetime, idle_timeoutApply only to sessions acquired after the reload. Each session stores its expiry and idle timeout at creation, so existing sessions are never shortened or extended by a reload.
[[management.admin]]Read on every management request. A removed administrator is refused on its next request; a changed verifier applies immediately. A name used by an API principal rejects the reload and is refused at startup.
[management] tls cert_file, key_file, and file contentsRe-read on every reload. New management connections use the new certificate; open connections keep theirs.

Restart-only

A changed restart-only setting is ignored with a warning naming the setting, never its value. Reloadable settings still apply.

SettingEffect
listen, admin_listen, [management] listenListener sockets are bound at startup.
root_key_file / NUNYA_ROOT_KEY (the root key itself)Every scope key derives from it. Replacing it is an explicit continuity break; see root-key recovery.
state_dirThe service holds exclusive ownership of the store for its lifetime.
[upstream] route_id, [spanner_native] route_idThe route ID is an input to scope derivation. Changing it would change every token on the route.
[upstream] connection keys: host, port, user, password_file / NUNYA_UPSTREAM_PASSWORD, dbname, tls, ca_file, connect_timeout_ms, application_name, dialectUpstream connections and the catalog dialect are set up at startup. The dialect key is upstream.dialect.
[spanner_native] listen, database, emulator_endpoint, endpoint; adding or removing the sectionThe route is set up at startup.
policy, [upstream] policy, [spanner_native] policy (paths)Reload units are fixed at startup. The file contents still reload.
policy_watch_msWatchers are started at startup.
allow_plaintext; adding or removing [tls]Changing whether agent listeners accept plaintext or TLS changes the security posture and needs a restart.
Adding or removing [management] or its tlsThe management listener shape and its TLS requirement off loopback are checked when it starts.

Management enablement and listen addresses require a restart because sockets bind at startup. Certificates and admin entries reload because they are read per connection and per request, like the agent routes.

Kubernetes peer state (preview)

The optional [kubernetes.peer] section accepts listen (default 0.0.0.0:6482), secret_file (required; a mounted Kubernetes Secret containing at least 32 bytes), and counter_batch (default 16, maximum 64). Multi-replica serving remains unsupported. Keep the peer port on the pod network behind a NetworkPolicy: request bodies are authenticated but not encrypted; responses are sealed.

Upgrading policy files

Service keyMeaning
snapshot_max_age_msNonnegative integer; default 60000. Maximum catalog snapshot age.
[readlog]Service-wide audit sink. See the read-log reference for sink, path and max_bytes.
[readlog] max_filesRotated predecessors for the file sink. Integer from 1 to 1000, default 10.

No version line means a legacy policy with Show by default and the current explicit rules. Legacy readlog and snapshot_max_age_ms are still accepted. They now belong in service configuration: put snapshot_max_age_ms at top level and [readlog] in nunya.toml. If both service and legacy file specify a setting, they must agree. The default snapshot age is 60000 ms; a read-log sink must be supplied.

[readlog]
sink = "file"
path = "read.log"
max_bytes = 104857600
max_files = 10

To migrate, move those infrastructure settings out of the policy, add version = 2 and choose default = "show" to retain visibility or default = "tokenize" to protect unlisted columns. Version 2 rejects infrastructure settings in the policy. Validate and preview before applying: preview reports newly visible, masked and tokenized columns, domain changes, added/removed links, repairs needed, mode change, counts and a catalog fingerprint. Tokenize can mask unsupported types and whole JSON columns without path rules; inspect the effective policy.

nunya policy import <route> transfers a file-owned route to durable service ownership. See policy management for expected revisions, retry keys and returning to file ownership. A configured policy_owner = "file" blocks import until removed and restarted.
