Loading and route selection

Unknown fields and invalid types are errors. Nunya collects independent errors using data-free diagnostics. Configure at least one route: a PostgreSQL-wire upstream, a native Spanner listener, or both. An upstream section requires a valid top-level listener. A native-only configuration may omit both the upstream section and top-level listener.

nunya policy check --config nunya.toml
nunya serve --config nunya.toml

root_key_file = "root.key"

schemas = ["public"]

snapshot_refresh_ms = 30000
max_connections = 256
allow_plaintext = true

This fragment is a trusted-local example. Add an upstream section before using it.

Credentials and environment variables

The loader reads only the following two secret environment variables as configuration fallbacks. It does not expand environment references inside TOML strings.

KeyType / defaultMeaning and validation
NUNYA_ROOT_KEYenvironment string; no defaultUsed only when root_key_file is absent. Supply 64 hexadecimal characters. Root key input accepts exactly 32 raw bytes, or trimmed UTF-8 text containing 64 hexadecimal characters.
NUNYA_UPSTREAM_PASSWORDenvironment string; no defaultUsed only when upstream.password_file is absent. Must decode as UTF-8. Trailing CR and LF characters are removed.

A configured secret file wins over its environment variable. An unreadable or invalid file produces an error; it does not fall back to the environment. Root key material is held in zeroizing storage. Keep keys, task state, password files and SCRAM verifiers private.

umask 077
nunya key generate > root.key
printf '%s\n' 'your-upstream-password' > upstream.password

The command writes a fresh 32-byte key as lowercase hex. The password above is a placeholder to replace locally, never a shipped credential.

Inbound TLS keys

The same inbound certificate and key serve the configured routes. Under [tls], both paths are required. The loader reads PEM certificate and private-key material and constructs a server configuration; missing, malformed or incompatible material fails validation. Client certificates are not required by this TLS configuration; agents authenticate with their task or standing credentials.

KeyType / defaultMeaning and validation
cert_filenonempty path; required in tlsPEM server certificate chain.
key_filenonempty path; required in tlsPEM private key.
[tls]
cert_file = "server-chain.pem"
key_file = "server-key.pem"

Omit the entire TLS section only with an explicit trusted-local plaintext setting. Adding a TLS section still requires valid certificate material even if plaintext is allowed.

Standing identity keys

Use repeated [[standing]] tables. No identities are configured by default.

KeyType / defaultMeaning and validation
namestring; requiredUnique, nonempty login name. Names beginning task: are reserved and refused.
verifierstring; requiredValid PostgreSQL SCRAM-SHA-256 verifier: positive decimal iterations, base64 salt, and 32-byte decoded stored/server keys.
nunya standing hash

Enter one password line on standard input. Copy the generated verifier into the entry below; the bracketed value is an illustrative placeholder, not a usable verifier.

[[standing]]
name = "reporting-agent"
verifier = "<generated SCRAM-SHA-256 verifier>"

Native Spanner keys

Under [spanner_native], unknown keys are errors. Both routes share policy, root key, task store, standing identities and inbound TLS. Native support has been tested against the emulator only.

KeyType / defaultMeaning and validation
listensocket-address string; requiredAgent gRPC listener address.
databasestring; requiredExactly projects/PROJECT/instances/INSTANCE/databases/DATABASE with all three identifiers nonempty.
emulator_endpointstring; omittedMust start with the HTTP scheme. Explicit trusted plaintext emulator route, without Google credentials; takes precedence over endpoint when both are present.
endpointstring; default Google Spanner HTTPS serviceMust start with the HTTPS scheme. Selects a trusted production endpoint when no emulator endpoint is configured.
snapshot_refresh_mspositive integer; 30000Native snapshot refresh interval. This is separate from the top-level PostgreSQL interval.
[spanner_native]
listen = "127.0.0.1:6433"
database = "projects/my-project/instances/my-instance/databases/my-database"
emulator_endpoint = "http://127.0.0.1:9010"
snapshot_refresh_ms = 30000

The production default endpoint is the HTTPS service at spanner.googleapis.com. Production upstreams use Google credentials. For a native-only file omit the upstream section and top-level listen key; still supply policy, root key, state directory and either TLS or explicit plaintext permission. There is no admin listener for native-only operation. Restart to change its policy.
