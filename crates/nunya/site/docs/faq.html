Questions worth asking before you connect

Practical answers about hidden values, permitted work and the limits of the gateway.

Why not a read replica with masked views?

A masked view can remove read values. This workflow also needs to carry a hidden address into an approved write. Nunya returns a scoped token and decodes it in a permitted domain. Database permissions and views may still be useful controls alongside the gateway.

What does NY001 mean?

A token was used outside its domain. In the demo the agent writes an email token into notes.body, a plain free-text destination. The write is refused and no note is stored. Move values only between columns deliberately assigned to a compatible shared domain.

Can the agent join on a blind column?

Yes, using allowed equality joins with compatible columns in the same domain. Equality relationships remain visible. This does not permit arbitrary functions, patterns, sorting or range comparisons on hidden values. Check the SQL support page for the precise contract.

What happens when a task expires?

New PostgreSQL authentication fails, but already authenticated PostgreSQL sessions retain scope keys and are not generally terminated by expiry or close. Explicit tokenization checks liveness again. Native Spanner checks task authentication per RPC, including cached sessions. Do not use expiry as an immediate PostgreSQL session-kill control.

Does Nunya replace stored database values?

No. The demo outbox stores carol@example.test while the agent submits and reads back an email token. Nunya transforms approved inputs and protected outputs at the gateway boundary. The upstream database must remain inaccessible to the agent.

Are tokens hashes?

Text tokens are deterministic authenticated AES-SIV ciphertext with a domain prefix and base32 body. Other supported types use type-preserving conversion. Nunya reverses this conversion for approved inputs; a one-way hash would not support that workflow.

Can I reuse a token in another task?

Do not rely on it. Tokens belong to a domain and scope. Text tokens authenticate that scope; numeric/date and UUID permutations have no authentication tag, so a wrong-scope typed token may decode to a different value rather than being refused. Each task has a random scope salt. PostgreSQL standing sessions receive a new salt when connecting, so their tokens are not a reconnect-stable identity scheme.

Can the agent still run analytics?

Ordinary analysed analytics work on plain columns. The demo groups by country and returns identical counts on both paths. Blind columns have a narrower contract, including grouping and counts, rather than unrestricted arithmetic and aggregation.

What if the agent already knows an email?

An operator can enable nunya_tokenize for the domain with a bounded per-task quota. It creates a token for an approved lookup. It defaults to off; review the guessing implications before enabling it. Explicit tokenize plaintext arguments are redacted from the read log.

Do I need a special driver?

The PostgreSQL route speaks the PostgreSQL wire protocol. Point the agent at Nunya using its task or standing credential. The supplied qualification reports psycopg 3 and pgJDBC 42.7.3 passing a seven-step check. SQL and protocol compatibility still follow the documented gateway limits.

Is Spanner production-tested?

Both PGAdapter and native GoogleSQL routes pass against the emulator. A real-Spanner run has not happened yet. Native GoogleSQL tokens must be query parameters; literals are never decrypted. Review route-specific limitations before deployment.

How much latency does it add?

Nunya adds one network hop. Latency has not been measured, so there is no benchmark number to quote. Measure your deployment and workload before making a performance commitment.

What if the agent gets the upstream password?

That is outside the protection model. Database credentials and a network path can bypass the gateway. Keep upstream secrets away from the agent, isolate the upstream network and operate Nunya under a protected account.

Can a refusal reveal a hidden value?

Gateway refusals have fixed NY001-NY010 messages; static internal hints are omitted from agent-facing Display output. This does not make all operational artifacts public: logs can contain statements and tokens and need access controls.

Can I reload the policy?

The PostgreSQL route supports admin reload and Unix SIGHUP; an invalid policy retains the current policy. A Spanner policy change requires a restart. A native-Spanner-only deployment has no admin listener.

What should I try first?

Run the isolated PostgreSQL quickstart, mark protected columns, validate the policy and open a short-lived task. Reproduce the walkthrough's approved outbox write and refused notes write. Read the security model before connecting an agent.
