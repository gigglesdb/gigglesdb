Questions worth asking before you connect

Practical answers about hidden values, permitted work and the limits of the gateway.

Does my application connect through Nunya?

No. Applications keep their direct database connection. Nunya is a separate lane for agents: it returns tokens instead of protected values and refuses DDL and statements it cannot analyse.

Do I need to change my application?

No. Your application, connection string and drivers stay as they are. Principals authenticate only to the management API to acquire sessions. Agents connect to their own Nunya endpoint with access-session credentials; Nunya uses its own least-privilege upstream role.

Why not a read replica with masked views?

A masked view can remove read values. This workflow also needs to carry a hidden address into an approved write. Nunya returns a scoped token and decodes it in a permitted domain. Database permissions and views may still be useful controls alongside the gateway.

What does NY001 mean?

A token was used outside its domain. In the demo the agent writes an email token into notes.body, a plain free-text destination. The write is refused and no note is stored. Move values only between columns deliberately assigned to a compatible shared domain.

Can the agent join on a blind column?

Yes, using allowed equality joins with compatible columns in the same domain. Equality relationships remain visible. This does not permit arbitrary functions, patterns, sorting or range comparisons on hidden values. Check the SQL support page for the precise contract.

What happens when an access session ends?

Revocation, absolute or idle expiry, principal disablement and removal of a configured standing principal end active sessions. PostgreSQL cancels upstream work, stops releasing results and closes the connection with NY011; a forwarded write whose completion was not seen produces NY012 instead. Native Spanner checks liveness on every RPC and during active work. Never replay a write with an unknown outcome. See session errors.

Does Nunya replace stored database values?

No. The demo outbox stores carol@example.test while the agent submits and reads back an email token. Nunya transforms approved inputs and protected outputs at the gateway boundary. The upstream database must remain inaccessible to the agent.

Are tokens hashes?

Text tokens are deterministic authenticated AES-SIV ciphertext with a domain prefix and base32 body. Other supported types use type-preserving conversion. Nunya reverses this conversion for approved inputs; a one-way hash would not support that workflow.

Can I reuse a token after reconnecting?

Yes, when reconnecting or renewing the same active access session. Its durable scope salt and route binding keep tokens stable across reconnects and service restarts when the state directory and root key are preserved. A new session creates a different scope; tokens must not move between scopes or routes. Text tokens authenticate scope, but numeric/date and UUID tokens lack an authentication tag and may decode to the wrong value instead of being refused. Obtain fresh tokens after an explicit --new-scope replacement. See token scopes.

Can the agent still run analytics?

Ordinary analysed analytics work on plain columns. The demo groups by country and returns identical counts on both paths. Blind columns have a narrower contract, including grouping and counts, rather than unrestricted arithmetic and aggregation.

What if the agent already knows an email?

An operator can enable nunya_tokenize for a domain with both tokenize_limit_per_session and tokenize_limit_per_principal, bounded by tokenize_principal_window. It creates a token for an approved lookup and defaults to off. A new session or restart does not reset the principal window. Review the guessing implications before enabling it. Explicit tokenize plaintext arguments are redacted from the read log.

Do I need a special driver?

The PostgreSQL route speaks the PostgreSQL wire protocol. Log in as session:REPLACE_WITH_SESSION_ID with the session secret; principals authenticate only to the management API. Nunya accepts a small exact allowlist of pgJDBC/HikariCP session-metadata statements, including SHOW TRANSACTION ISOLATION LEVEL and current schema/catalog queries. This does not permit arbitrary catalog SQL. See drivers and metadata compatibility.

How do I connect to Spanner?

Use the PostgreSQL route through PGAdapter or the native GoogleSQL gRPC route. Native authentication uses Authorization: Bearer nunya.session:REPLACE_WITH_SESSION_ID.REPLACE_WITH_SESSION_SECRET. Native GoogleSQL tokens must be query parameters; literals are never decrypted. Each route can use its own policy file. Review Spanner setup and route-specific limitations before deployment.

What if the agent gets the upstream password?

That is outside the protection model. Database credentials and a network path can bypass the gateway. Keep upstream secrets away from the agent, isolate the upstream network and operate Nunya under a protected account.

Can a refusal reveal a hidden value?

Gateway refusals have fixed NY001-NY012 messages; static internal hints are omitted from agent-facing Display output. This does not make all operational artifacts public: logs can contain statements and tokens and need access controls.

Can I reload the policy?

Policy contents reload for PostgreSQL and native Spanner, with independent validation for distinct policy files. All route policies must name the same read-log sink. Invalid policy updates retain the previous policy. TLS certificates and selected configuration settings also reload; listener addresses, policy file paths, route IDs, the root key and state directory need a restart. See reloadable and restart-only settings.

Keep state_dir on local disk only, with one service owning it. The management Unix socket is unavailable on Windows; configure the management TCP listener and administrator credentials there. See operations.

What should I try first?

Run the isolated PostgreSQL quickstart, mark protected columns, validate the policy and acquire a short-lived access session. Reproduce the walkthrough's approved outbox write and refused notes write. Read the security model before connecting an agent.
