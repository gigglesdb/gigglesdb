A working boundary for database agents

Nunya sits between your agent and your database. The agent gets useful SQL access; protected values leave as tokens.

Start with a real query

An agent following up on missed payments needs customer identifiers and a way to queue reminders. It does not need to see an email address. Nunya lets it carry a token from a protected customer column to an approved outbox column. The database stores the real address; the agent reads the token again.

Start with the local PostgreSQL quickstart, then follow the eight-action walkthrough to see the same SQL with and without the gateway. All displayed results come from the recorded demo, including refusals and the underlying stored row.

Understand the boundary first

Every sensitive column must be marked in the policy. An unmarked column is plain and passes through. The agent must have no direct route to the upstream database and must never receive upstream credentials. Protect the Nunya host, root key, state directory, task secrets and logs.

Tokens preserve equality within a domain and scope. Repeated values and counts can remain visible. Nunya is a controlled SQL gateway, not a promise to hide every fact about a dataset. Read Security and Limitations before exposing a route.

PostgreSQL and two Spanner routes

PostgreSQL agents connect over the PostgreSQL wire protocol. Spanner can use that route through PGAdapter, or a native GoogleSQL gRPC route. Both Spanner routes have been tested against the emulator only; a real-Spanner run has not happened yet.

Qualification supplied with this task, verified on 2026-11-15/16, reports the worked example passing on PostgreSQL 16, 17 and 18, and psycopg 3 and pgJDBC 42.7.3 passing a seven-step driver check. These are specific compatibility results, not a claim that every driver or query is supported.

Use the CLI reference for commands, error catalog for NY001-NY010, and policy reference for validation rules. If an operation cannot be fully analysed or safely handled, the gateway refuses it. The FAQ connects common design questions to the corresponding controls.
