Quickstart

Deploy the gateway once, provision an identity, then connect with an access session. Your application keeps its direct database connection.

Start with a Spanner emulator

Install nunya and start the local Spanner emulator harness. Save these two keys in nunya.toml in a private directory.

[spanner_native]
database = "projects/test-project/instances/test-instance/databases/gsql"
emulator_endpoint = "http://127.0.0.1:9010"

Start the gateway from that directory.

nunya serve --config nunya.toml

Nunya creates state/root.key, state/operator.secret and a starter policy.toml on a fresh local start. The starter policy tokenizes unlisted columns. Keep your state directory private. The management listener is on 127.0.0.1:6481 and the native listener is on 127.0.0.1:6433.

In a second terminal in the same directory, create a principal, grant access, and acquire a session.

nunya principal create reporting-agent --kind agent --generate-secret --secret-out principal.secret
nunya principal grant reporting-agent --route spanner-native=read-only
nunya session acquire --principal reporting-agent --principal-secret-file principal.secret --route spanner-native --ttl 1h

Use nunya session env to obtain the native connection environment. See native authentication for client setup.

PostgreSQL: deploy once

Install psql and make nunya available on your PATH. To build Nunya from source, run cargo build --release from crates/nunya and add its target/release directory to PATH. On Windows, point LIBCLANG_PATH to your LLVM bin directory before building. pg_query uses bindgen.

$env:LIBCLANG_PATH = "C:\Program Files\LLVM\bin"
cargo build --release

For a seeded local database, start Docker with Compose and run this command from crates/nunya in a Bash terminal. Choose a writable private work directory. The harness starts PostgreSQL 16, 17 and 18 on loopback ports 16432, 17432 and 18432. Keep it running. This example uses PostgreSQL 16 and its public test password in an isolated local environment.

bash harness/run.sh --work-root /path/to/private/work

Work in a new private configuration directory in a second terminal. On Unix, set umask 077 before creating files. On Windows, use a directory with a private ACL. Copy crates/nunya/harness/policy.toml from the checkout to this directory as policy.toml. It blinds email addresses, masks phone numbers and leaves country and payment counts plain.

Save this configuration as nunya.toml in the same directory.

[upstream]
host = "127.0.0.1"
port = 16432
user = "nunya"
dbname = "app"
password_file = "upstream.password"

Write the upstream password and start the gateway. In Bash:

printf '%s\n' 'nunya-harness-only' > upstream.password
nunya serve --config nunya.toml

In PowerShell:

'nunya-harness-only' | Set-Content -Encoding Ascii upstream.password
nunya serve --config nunya.toml

Leave the gateway running. The default listeners use plaintext on loopback. For remote traffic use verified TLS, including on the management listener. See configuration and policy reference.

2. Provision an identity

Open another trusted terminal in the configuration directory. Create a principal with its own credential file, then grant it read-only access to the PostgreSQL route.

nunya principal create reporting-agent --kind agent --generate-secret --secret-out principal.secret
nunya principal grant reporting-agent --route postgres=read-only

The create command prints the principal ID and saves the agent secret in the new principal.secret file. Keep the administrator and upstream credentials in the trusted operator environment. See principal commands for credential expiry and grant replacement.

3. Connect

In the same terminal, select a fresh helper state directory for this example. In Bash use export NUNYA_HOME="$PWD/session-home". In PowerShell use $env:NUNYA_HOME = Join-Path $PWD 'session-home'. Acquire an access session into the default context.

nunya session acquire --principal reporting-agent --principal-secret-file principal.secret --route postgres --ttl 1h

Load the connection environment and start plain psql in that shell. In Bash:

eval "$(nunya session env)"
psql

In PowerShell:

nunya session env --format powershell | Invoke-Expression
psql

The exports give the agent everything required to connect, including PGDATABASE=app, PGHOST, PGPORT, PGUSER and PGPASSWORD. The host and port come from the route advertised by Nunya. For container port mappings or NAT, set advertise_host and advertise_port in configuration or override them when acquiring the session with --pg-host and --pg-port. Here session env uses the stored session and reports on stderr that it skipped server revalidation. Keep the exports and the helper's sessions.json private. Give the agent the session environment while keeping the principal and upstream secrets in the trusted shell.

At the psql prompt, run this query. Email addresses arrive as session-scoped tokens and the seeded phone numbers arrive as placeholders. The read-only grant refuses writes.

SELECT id, email, phone FROM customers ORDER BY id;

Reconnecting or renewing an active session preserves the token scope. Renewal refreshes idle time within the absolute expiry. Once a stored session ends, --new-scope explicitly permits replacement. Obtain fresh tokens for the replacement. See the walkthrough for token reuse after reconnecting and drivers for other clients.

Cleanup

Exit psql with \q. Revoke the session while the service is still running:

nunya session revoke --principal-secret-file principal.secret

Stop the foreground service with Ctrl-C. Press Enter in the harness terminal to remove its containers and volumes. Close the session shell to discard its exported credentials. Protect or remove the private demonstration credentials, configuration and state when finished.
