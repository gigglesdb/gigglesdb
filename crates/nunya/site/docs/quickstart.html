Quickstart

Run the isolated local PostgreSQL harness, open a short-lived task, and connect through Nunya. These commands use Bash on the project's Windows development setup; the harness requires a task directory under J:/gigglesdb-work.

On this page
  • Prepare the tools
  • Start the local database
  • Create a private configuration
  • Open a task and serve
  • Connect as the agent
  • Close the task and stop

Prepare the tools

Have Docker with Compose, Bash, psql, the Rust toolchain and clang/libclang available. From crates/nunya, build the binary using this checkout's shared build tools and a private task output directory. The local walkthrough takes about ten minutes once these prerequisites are ready; source compilation and image downloads take additional time. Replace the task directory name if it already exists.

mkdir -p J:/gigglesdb-work/nunya-docs-demo/tmp
export TEMP=J:/gigglesdb-work/nunya-docs-demo/tmp
export TMP="$TEMP"
export CARGO_TARGET_DIR=J:/gigglesdb-work/nunya-docs-demo/target
export RUSTC_WRAPPER=J:/gigglesdb-work/tools/bin/sccache.exe
export SCCACHE_DIR=J:/gigglesdb-work/sccache-cache
export SCCACHE_CACHE_SIZE=100G
export CARGO_INCREMENTAL=0
export CARGO_BUILD_JOBS=4
export LIBCLANG_PATH=J:/tools/LLVM/bin
bash J:/gigglesdb-work/r2/buildslot2.sh cargo build --release
export PATH="/j/gigglesdb-work/nunya-docs-demo/target/release:$PATH"

The commands below run from that same crate directory. The database password in this harness is public test data, suitable only for isolated local development. Keep the build environment and PATH in each terminal that uses Nunya.

Start the local database

bash harness/run.sh --task-root J:/gigglesdb-work/nunya-docs-demo

Keep this terminal open. The script starts PostgreSQL 16, 17 and 18 on loopback ports 16432, 17432 and 18432, waits for health checks, and seeds an app database. It prints 'PostgreSQL 16/17/18 ready on 16432/17432/18432. Press Enter to stop.' Logs and temporary files are placed below the task root. Pressing Enter removes this run's containers and volumes.

Create a private configuration

umask 077
mkdir -p J:/gigglesdb-work/nunya-docs-demo/config
cp harness/nunya.toml harness/policy.toml J:/gigglesdb-work/nunya-docs-demo/config/
export NUNYA_ROOT_KEY="$(nunya key generate)"
export NUNYA_UPSTREAM_PASSWORD=nunya-harness-only
export NUNYA_CONFIG=J:/gigglesdb-work/nunya-docs-demo/config/nunya.toml
nunya policy check --config "$NUNYA_CONFIG"

Run this in a second terminal and retain its environment. key generate emits a fresh root key; policy check loads configuration, opens the state and read-log sink, connects to the catalog and validates the policy. Success prints policy OK. The copied configuration selects port 16432. Change upstream.port to 17432 or 18432 to select another harness version. Relative policy and state paths resolve beside the configuration.

The harness policy makes customers.email and outbox.to_address blind in the email domain, masks customers.phone with [hidden], and leaves country and payment counts plain. It explicitly permits local plaintext via allow_plaintext. Review Policy reference before using any other schema.

Open a task and serve

nunya task open --config "$NUNYA_CONFIG" --ttl 30m --label documentation
nunya serve --config "$NUNYA_CONFIG"

task open prints user: task:<id>, a one-time secret, and expires_unix_ms. Save the secret securely now: it cannot be shown again. --ttl accepts positive integer durations ending in s, m or h. serve keeps running; preserve the same root-key and upstream-password environment for it.

Connect as the agent

psql 'host=127.0.0.1 port=6432 dbname=app user=task:REPLACE_WITH_ID sslmode=disable'

Replace the ID and enter the printed task secret at the password prompt. This connects to Nunya, not directly to PostgreSQL. Run:

SELECT id, email, phone FROM customers
WHERE failed_payments >= 2 ORDER BY id;
SELECT country, count(*) FROM customers GROUP BY country;

Emails arrive as task-scoped tokens and phones as placeholders. Country analytics remain ordinary SQL. See the walkthrough for captured direct-versus-gateway results and a same-domain write. Never copy tokens into a different domain or a plain column.

Close the task and stop

nunya task list --config "$NUNYA_CONFIG"
nunya task close --config "$NUNYA_CONFIG" REPLACE_WITH_ID

Use a third terminal with the same environment. task list shows live IDs, expiries and labels without secrets; task close prevents new authentication for the selected task and prints task closed. Stop Nunya with Ctrl-C, then press Enter in the harness terminal. The PostgreSQL service permits sessions up to 30 seconds to drain. Protect or remove your private local configuration and state when finished.
