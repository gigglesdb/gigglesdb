CLI reference

The complete operator command surface. Run commands from a trusted shell; session secrets, principal secrets, root keys and verifier output are credentials.

Commands and help

Commands are lowercase. There is no default configuration path or version flag: use version. Clap supplies --help, -h and the help subcommand. Application flags have no short aliases.

nunya --help
nunya session acquire --help
nunya help policy check

Version and service

version prints the package version and a newline. Its value follows the built package, so no sample version is asserted here.

serve requires --config PATH, loads configuration, then runs the configured routes and snapshot refresh. The private administration listener starts for either route. Ctrl-C or SIGTERM begins shutdown and permits up to 30 seconds for sessions to drain.

nunya version
nunya serve --config /etc/nunya/nunya.toml

Policy check

policy check requires --config PATH. It loads configuration and TLS material, opens the read-log sink, captures every configured route's catalog and validates each route's selected policy file against that route's catalog. Each route uses its own policy key, or the top-level fallback; see policy file selection. It needs upstream access and writable log storage; it is not an offline TOML-only check.

nunya policy check --config nunya.toml

The successful output is exactly:

policy OK

Invalid input yields sanitized diagnostics on stderr, one per line, and exit status 1.

Access sessions and exec

Every session, exec, principal and connections command accepts these management options:

FlagValue / default
--serverRequired URL; NUNYA_SERVER fallback. HTTP or HTTPS, or unix:/path/to/nunya.sock on Unix.
--ca-fileOptional path; NUNYA_CA_FILE fallback. Trusted CA for HTTPS.
--principalOptional name; NUNYA_PRINCIPAL fallback. Required for bearer authentication.
--principal-secret-fileOptional path; first line is the principal secret. Otherwise reads NUNYA_PRINCIPAL_SECRET (helper fallback, not a clap flag).
--contextOptional stored context name; helper uses default when omitted.

Principal credentials authenticate only to the management API. Session credentials authenticate only to database ports. The Unix service socket grants administrator authority without a bearer credential.

session acquire and exec also accept: --route ROUTE (default postgres), --mode MODE (read-only or read-write; omitted selects the granted mode), --ttl DURATION (omitted uses the server maximum), --label TEXT (optional audit data), --new-scope, --rotate, --pg-host HOST (NUNYA_PG_HOST, default 127.0.0.1), and --pg-port PORT (NUNYA_PG_PORT, default 6432; unsigned 16-bit integer). Boolean flags default to false. TTL is positive decimal digits followed by one lowercase s, m, h or d, without spaces or fractions, within unsigned 64-bit seconds. The server refuses a lifetime above its configured maximum.

session acquire creates or resumes a context. Only this command accepts --isolated: it creates a separate token scope and, without an explicit context name, an automatically named context. An existing explicit context cannot be overwritten by isolation. Labels never select, merge or grant access. --rotate conflicts with --new-scope and --isolated.

nunya session acquire --server https://gateway.example:6481 --principal reporting-agent --principal-secret-file principal.secret --context reporting --isolated --label reporting --ttl 1h

A reconnect or renewal preserves scope. An ended stored session refuses continuation until --new-scope explicitly permits replacement; obtain fresh tokens for the replacement scope. --rotate rotates an existing session credential using salt and iterations stored when this helper acquired it; sessions without those stored parameters require a new acquisition. The old credential remains valid until the session ends.

session show prints public details. session renew accepts the common options plus optional --mode MODE and --rotate; it revalidates principal and grants and extends idle time within the absolute lifetime. session revoke revokes and removes the stored context. session env accepts --format sh|powershell (default sh) and prints PostgreSQL environment credentials; treat the output as secret.

nunya session show --server https://gateway.example:6481 --principal reporting-agent --context reporting
nunya session renew --server https://gateway.example:6481 --principal reporting-agent --context reporting --rotate
nunya session env --server https://gateway.example:6481 --principal reporting-agent --context reporting --format powershell
nunya session revoke --server https://gateway.example:6481 --principal reporting-agent --context reporting

exec acquires or resumes a context and runs the required child command after -- with PostgreSQL environment credentials. It accepts the acquisition flags above, but no --isolated.

nunya exec --server https://gateway.example:6481 --principal reporting-agent --principal-secret-file principal.secret --context reporting -- psql -c "SELECT 1"

The helper uses NUNYA_HOME when set; otherwise Unix uses XDG_STATE_HOME/nunya or HOME/.local/state/nunya, and Windows uses LOCALAPPDATA/nunya. Keep its sessions.json private.

Principals and connections

All commands below accept the common management options above and require administrator authority. TARGET is a principal name or 32-hex identifier. Creation requires a name and --kind person|agent|service; --admin defaults to false. --generate-secret and --verifier VERIFIER conflict. Creation without either makes an identity without a credential; credential add requires one. Generated secrets are printed once.

nunya principal create reporting-agent --kind agent --generate-secret --server unix:/var/lib/nunya/nunya.sock
nunya principal list --server unix:/var/lib/nunya/nunya.sock
nunya principal show reporting-agent --server unix:/var/lib/nunya/nunya.sock
nunya principal disable reporting-agent --server unix:/var/lib/nunya/nunya.sock
nunya principal enable reporting-agent --server unix:/var/lib/nunya/nunya.sock
nunya principal credential add reporting-agent --generate-secret --expires 1d --server unix:/var/lib/nunya/nunya.sock
nunya principal credential delete reporting-agent 0123456789abcdef0123456789abcdef --server unix:/var/lib/nunya/nunya.sock
nunya principal grant reporting-agent --route postgres=read-only --server unix:/var/lib/nunya/nunya.sock
nunya principal grant reporting-agent --none --server unix:/var/lib/nunya/nunya.sock
nunya connections list --server unix:/var/lib/nunya/nunya.sock

credential add --expires DURATION is optional (no expiry when omitted), using the same duration grammar as TTL. A principal can hold at most four active credentials; a fifth credential add is refused with credential_limit until one is deleted or expires. A retried add with the same idempotency key returns the credential it already created. credential delete requires a second positional credential hex ID. grant replaces every grant: repeat --route ROUTE=read-only or --route ROUTE=read-write, or use --none to remove all. These alternatives conflict; one is required. Duplicate routes are refused. Config-managed principals cannot be disabled, enabled or re-credentialed through this API; their grants can be changed. connections list lists active connections.

Standing verifier generation

standing hash takes no flags or positional arguments. It reads one password line from stdin, removes one line ending, generates a random 16-byte salt, and emits a PostgreSQL SCRAM-SHA-256 verifier using 4096 iterations.

nunya standing hash

Illustrative output layout; salt and key material are generated, not fixed:

SCRAM-SHA-256$4096:<base64-salt>$<base64-stored-key>:<base64-server-key>

Place that output in the verifier field of a [[standing]] config-managed principal or a [[management.admin]] entry. It is not a database login. Protect it as a credential. No input line is a failure. This command does not edit the configuration or acquire a session.

Root key generation

key generate takes no flags or positional arguments. It fills 32 bytes from the system random source and prints 64 lowercase hexadecimal characters plus a newline.

umask 077
nunya key generate > root.key

Set root_key_file in the top-level configuration to this private file, or provide the root key environment fallback. Generating a key does not update the configuration. Replacing the root key is an explicit continuity break: existing tokens no longer decode.

Exit codes and diagnostics

Successful commands return 0. Runtime, configuration and service failures return 1 with diagnostics on stderr. The session helper returns 2 when an ended stored scope requires explicit replacement. exec returns its child's exit code, or 1 when no exit code is available. This CLI also converts Clap parse failures to exit 1 (and help to exit 0). Do not assume Clap's usual parse-error exit code of 2. Help output goes to stdout; parse diagnostics use stderr. A successful long-running serve command returns only after shutdown.

Credentials are deliberately absent from config diagnostics. Fix the named field using the configuration reference, then run policy check before starting the service.
