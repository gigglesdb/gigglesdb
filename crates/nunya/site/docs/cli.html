CLI reference

The complete operator command surface. Run commands from a trusted shell; task secrets, root keys and verifier output are credentials.

Commands and help

The command tree is shown below as a source-derived synopsis, not captured terminal output. Commands are lowercase, with spaces separating subcommands. There is no global configuration-file default and no version flag: use the version command.

nunya version
nunya serve --config <PATH>
nunya policy check --config <PATH>
nunya task open --config <PATH> --ttl <DURATION> [--label <LABEL>]
nunya task close --config <PATH> <ID>
nunya task list --config <PATH>
nunya standing hash
nunya key generate

Clap also supplies --help (short -h) on command levels and the help subcommand for navigating help. For example:

nunya --help
nunya task open --help
nunya help policy check

The only application flags are --config, --ttl and --label. None has a short alias. Required positional ID is used only by task close.

Version and service

version prints the package version and a newline. Its value follows the built package, so no sample version is asserted here.

serve requires --config PATH, loads configuration, then runs the configured routes and snapshot refresh. The PostgreSQL route also starts administration. Ctrl-C or SIGTERM begins shutdown and permits up to 30 seconds for sessions to drain.

nunya version
nunya serve --config /etc/nunya/nunya.toml

Policy check

policy check requires --config PATH. It loads configuration and TLS material, opens the task store and read-log sink, captures every configured route's catalog and validates the policy against it. It needs upstream access and writable state/log storage; it is not an offline TOML-only check.

nunya policy check --config nunya.toml

The successful output is exactly:

policy OK

Invalid input yields sanitized diagnostics on stderr, one per line, and exit status 1.

Task credentials

task open requires --config PATH and --ttl DURATION. Optional --label LABEL stores a human-readable label. Labels are not secrets and are listed with the task.

TTL is positive decimal digits followed by lowercase s, m or h. Examples: 3600s, 30m, 2h. Fractions, negatives, 0s, bare numbers, other units and values that overflow milliseconds are rejected. There is no default TTL.

nunya task open --config nunya.toml --ttl 30m --label reporting

Source-derived stdout layout (angle brackets are illustrative placeholders):

user: task:<task-id>
secret: <one-time-secret>
expires_unix_ms: <unix-milliseconds>

The fixed stderr reminder is:

Save this secret now; it cannot be shown again.

Save the secret immediately. Connect with the printed user and secret. The CLI cannot recover the secret later.

list requires --config PATH and prints live tasks without secrets, one per line, with tab-separated fields. Empty stores produce no rows. Illustrative layout:

nunya task list --config nunya.toml
# stdout layout, tab-separated:
task:<task-id>    <expiry-unix-ms>    <label-or-empty>

close requires --config PATH and a positional task ID. Both the bare ID and task:-prefixed form are accepted. Closing blocks future PostgreSQL logins and subsequent native RPC authentication; an already authenticated PostgreSQL session retains its scope keys. Explicit plaintext tokenization rechecks live task state. An invalid ID or unknown task is an error.

nunya task close --config nunya.toml <task-id>

Successful close output is exactly:

task closed

Standing verifier generation

standing hash takes no flags or positional arguments. It reads one password line from stdin, removes one line ending, generates a random 16-byte salt, and emits a PostgreSQL SCRAM-SHA-256 verifier using 4096 iterations.

nunya standing hash

Illustrative output layout; salt and key material are generated, not fixed:

SCRAM-SHA-256$4096:<base64-salt>$<base64-stored-key>:<base64-server-key>

Place that output in a configured standing identity's verifier field. Protect it as a credential. No input line is a failure. This command does not edit the configuration or create a task.

Root key generation

key generate takes no flags or positional arguments. It fills 32 bytes from the system random source and prints 64 lowercase hexadecimal characters plus a newline.

umask 077
nunya key generate > root.key

Set root_key_file in the top-level configuration to this private file, or provide the root key environment fallback. Generating a key does not update the configuration. Root-key changes alter scope keys: plan credential and token lifecycles before replacing it.

Exit codes and diagnostics

Successful commands return 0. Runtime, configuration and service failures return 1 with diagnostics on stderr. This CLI also converts Clap parse failures to exit 1 (and help to exit 0). Do not assume Clap's usual parse-error exit code of 2. Help output goes to stdout; parse diagnostics use stderr. A successful long-running serve command returns only after shutdown.

Credentials are deliberately absent from config diagnostics. Fix the named field using the configuration reference, then run policy check before starting the service.
