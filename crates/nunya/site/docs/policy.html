Policy reference

File structure and defaults

Policy TOML rejects unknown keys at every level and collects independent validation errors. Unlisted columns are plain: protect every sensitive column explicitly. The read-log table is required; domain and column collections may be omitted and then are empty. Parsing is followed by validation against a captured upstream schema.

KeyType / defaultMeaning and validation
snapshot_max_age_msnonnegative integer; 60000Maximum permitted snapshot age in milliseconds. Zero is accepted by the parser; once a snapshot is older than this limit, requests fail with NY008. This is independent of the refresh interval in gateway configuration.
readlogrequired tableRead-log destination; see the sink keys below.
domainstable; emptyNamed domain settings. A domain groups compatible protected columns; equality and approved writes can carry values within that domain.
columnarray of tables; emptyOne entry per protected column, written as [[column]]. Duplicate schema/table/column entries are errors.
snapshot_max_age_ms = 60000
[readlog]
sink = "stdout"
[domains.email]
tokenize = "on"
tokenize_limit_per_task = 20
[[column]]
table = "public.customers"
name = "email"
blind = "email"
[[column]]
table = "public.outbox"
name = "to_address"
blind = "email"
[[column]]
table = "public.customers"
name = "phone"
masked = true
placeholder = "[hidden]"

Read-log keys

Under [readlog], configure the audit destination before starting the gateway. Relative file paths resolve against the policy file's directory.

KeyType / defaultMeaning and validation
sinkstring; requiredExactly stdout or file. No implicit valid sink is supplied when the table or key is missing.
pathstring; omittedRequired and nonempty for file. Parsed but unused for stdout.
max_bytespositive integer; 104857600File rotation threshold (100 MiB). Zero and negative values are invalid, including when sink is stdout.
[readlog]
sink = "file"
path = "read.log"
max_bytes = 104857600

A read-log failure prevents database work from proceeding. Logs may contain SQL and tokens; restrict their permissions. See operations.

Domain keys

Write each domain as [domains.email], substituting your domain name. Names contain 1-31 ASCII bytes, start with a lowercase letter, and otherwise contain lowercase letters, digits or underscores. A declared domain may be unused.

KeyType / defaultMeaning and validation
tokenizestring; "off"Exactly off or on. Enabling allows explicit token creation from supplied plaintext; it does not change ordinary protected-column tokenization.
tokenize_limit_per_taskinteger; no defaultRequired with on and must be 1 through 100000. It is parsed as an unsigned 32-bit integer even when off; the 1..100000 requirement applies when on.
rangetable; omittedOptional inclusive numeric interval. Without it the token codec uses the type's default range. Both endpoints are mandatory when present.
minsigned 64-bit integer; required in rangeInclusive lower bound; must not exceed max.
maxsigned 64-bit integer; required in rangeInclusive upper bound. Schema validation requires at least 1048576 distinct values and an interval fitting every participating type.
[domains.account_id]
tokenize = "off"
range = { min = 0, max = 1048575 }

The range example suits an integer domain with enough representable values. It is not valid for text or UUID domains. Date bounds are PostgreSQL epoch-relative days, from -730119 through 2921939 (Gregorian years 0001-9999). Timestamp and timestamptz bounds are epoch-relative microseconds from -730119 * 86400000000 through 2921940 * 86400000000 - 1. These numbers configure the codec; they are not a filter on query results.

Column keys

Each entry has exactly one treatment. Masking substitutes a string or SQL NULL; blinding preserves an approved token flow.

KeyType / defaultMeaning and validation
tablestring; requiredSchema-qualified table name with exactly one dot and a nonempty table component. For the native Spanner default schema use .Customers, including the leading dot.
namestring; requiredColumn name. The referenced column must exist in the captured schema.
blindstring; absentNames a declared domain. Cannot coexist with masked, even masked = false.
maskedboolean; absentWhen supplied it must be true. Cannot coexist with blind.
placeholderstring; omitted means SQL NULLAllowed only for masked treatment. A string placeholder requires a textual column; omit it for a non-textual masked column.
[[column]]
table = "public.customers"
name = "phone"
masked = true
# Omit placeholder to return SQL NULL.

Schema validation and safe rollout

Protected columns must belong to a Table relation, not a view. Blind types supported are text, varchar, bpchar, int4, int8, UUID, date, timestamp and timestamptz. Textual types share one family; all other types must match within a domain. int2 has too few values for safe encryption; boolean and enums must be masked. Numeric, bytea, JSON, JSONB, arrays and unknown types are refused for blinding.

Triggers, rules, row policies, generated columns and defaults that read a blind or masked column make the policy unsafe: Nunya cannot inspect what those objects copy. Views are skipped by this dependent-object validation, but a protected policy column itself still must be on a table. Resolve the dependent object rather than weakening the protection.

nunya policy check --config nunya.toml

This command loads credentials, opens state and read-log storage, connects to every configured catalog, and validates the policy against those snapshots. It is more than a syntax checker. On success its fixed output is:

policy OK

Reload the PostgreSQL route through its private admin endpoint or Unix SIGHUP after a successful check; invalid reloads keep the current policy. Changes to the native Spanner route's policy require a restart. See operations.
