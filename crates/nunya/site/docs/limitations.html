Known limitations

Native policy reload requires restart

Admin reload and Unix SIGHUP reload the PostgreSQL route only. The native Spanner context holds its own policy and has no reload branch; it still refreshes catalog snapshots. Restart Nunya to apply a native policy edit, including in a process serving both routes.

No native-only admin listener

The health, metrics and reload listener starts inside the PostgreSQL service. A process configured with only [spanner_native] has no admin HTTP endpoint. Do not treat failure to connect to port 6480 as evidence that a native-only listener failed to start.

Spanner index and partition features

A structured Read or StreamingRead with a non-empty index field is refused. PartitionQuery, PartitionRead and BatchWrite are refused RPCs. Partition tokens, data boost and non-default query modes are also rejected. Use supported table reads or analysed SQL and qualify their complete options.

Token-detection gaps in parameters

For PostgreSQL Bind values not consumed as approved blind counterparts, token detection examines text-format values and declared textual OIDs 25, 1042 and 1043. Binary values with unspecified OID 0 are not scanned. The gap also includes binary values declared with other non-text OIDs. Supply text parameters or correctly declared text types for token-bearing text; do not rely on the gateway detecting opaque binary payloads.

Native Spanner detection checks top-level string parameter values; it does not recurse into ARRAY or STRUCT values. A token nested there is outside the current detector. This is a boundary of token exfiltration detection, not permission to bypass the policy or a supported way to send blind counterparts.

GoogleSQL literals are not decrypted

The native proxy refuses rewrite plans requiring literal decryption because GoogleSQL literal rendering differs from PostgreSQL. Pass returned tokens through named query parameters with the appropriate type. Do not interpolate a token into GoogleSQL text.

No-op SETs cannot share a mixed batch

The PostgreSQL simple-query path accepts a batch made entirely of approved local no-op SET statements, but refuses a message that combines one with another statement kind using NY006. Send each initialisation SET in a separate request, or send only a SET-only batch. The exact values are in SQL support.

Read-log intent and completion entries

Successful ordinary forwarded PostgreSQL statements produce an intent record with rows 0 before forwarding and a completion record afterwards. This happens for both simple queries and executions over the extended protocol, not just prepared statements. Portal suspension and exceptional paths affect record boundaries; no-op SET and local tokenize paths also differ. Do not calculate executed query totals by counting log lines or treating the initial zero as a completed zero-row result.

Existing PostgreSQL sessions survive task expiry

Task expiry and close revoke subsequent PostgreSQL authentication but do not automatically disconnect an existing PostgreSQL connection or erase its scope keys. General queries on that connection do not revalidate task liveness. Explicit task tokenization does consult live task state. Close connections as part of immediate revocation procedures. Native Spanner revalidates task credentials on every RPC.

Qualification and SQL coverage

The worked example has passed on PostgreSQL 16, 17 and 18. psycopg 3 and pgJDBC 42.7.3 have passed the supplied seven-step driver check. Both Spanner routes have passed against the emulator; no real-Spanner run has happened. These checks cover specific workflows, not every client, server feature or query shape.

Unknown SQL, functions, operators and protocol features fail closed. An allowed function name does not allow transforming blind input. The gateway adds one network hop; latency has not been measured. Read security for network isolation, unmarked columns and visible equality/count relationships.
