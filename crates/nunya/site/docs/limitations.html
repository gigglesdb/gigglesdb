Known limitations

These are current implementation boundaries, not planned-feature promises. Build your deployment around them and test the exact statements and client options your agents need.

Reload boundaries

PostgreSQL and native Spanner policy contents reload through shared coordination. Distinct policy files validate independently; routes sharing a canonical file form one reload unit. All policies must name the same read-log sink. Policy paths, route IDs, listener addresses, root key and state directory need a restart; certificates and selected operational settings reload live. See reload boundaries for the complete list.

Protect the admin listener

The health, metrics and reload HTTP listener also runs in native-Spanner-only deployments. These endpoints are unauthenticated: isolate the listener from agents and public networks. Principal authentication belongs to the separate management API, not the admin HTTP listener.

Spanner index and partition features

A structured Read or StreamingRead with a non-empty index field is refused. PartitionQuery, PartitionRead and BatchWrite are refused RPCs. Partition tokens, data boost and non-default query modes are also rejected. Use supported table reads or analysed SQL and qualify their complete options.

What query results reveal

Text token length depends on the plaintext byte-length bucket, so a text token reveals the approximate length of its value.

When a masked column has a configured placeholder, a present value returns the placeholder and an absent value returns SQL NULL. That difference is visible in direct results even though IS NULL predicates on masked columns are refused. A mask without a placeholder returns SQL NULL for both.

Token-detection gaps in parameters

For PostgreSQL Bind values not consumed as approved blind counterparts, token detection examines text-format values and declared textual OIDs 25, 1042 and 1043. Binary values with unspecified OID 0 are not scanned. The gap also includes binary values declared with other non-text OIDs. Supply text parameters or correctly declared text types for token-bearing text; do not rely on the gateway detecting opaque binary payloads.

Native Spanner detection checks top-level string parameter values; it does not recurse into ARRAY or STRUCT values. A token nested there is outside the current detector. This is a boundary of token exfiltration detection, not permission to bypass the policy or a supported way to send blind counterparts.

GoogleSQL literals are not decrypted

The native proxy refuses rewrite plans requiring literal decryption because GoogleSQL literal rendering differs from PostgreSQL. Pass returned tokens through named query parameters with the appropriate type. Do not interpolate a token into GoogleSQL text.

No-op SETs cannot share a mixed batch

The PostgreSQL simple-query path accepts a batch made entirely of approved local no-op SET statements, but refuses a message that combines one with another statement kind using NY006. Send each initialisation SET in a separate request, or send only a SET-only batch. The exact values are in SQL support.

Read-log intent and completion entries

Successful ordinary forwarded PostgreSQL statements produce an intent record with rows 0 before forwarding and a completion record afterwards. This happens for both simple queries and executions over the extended protocol, not just prepared statements. Portal suspension and exceptional paths affect record boundaries; no-op SET and local tokenize paths also differ. Do not calculate executed query totals by counting log lines or treating the initial zero as a completed zero-row result.

Access-session termination

Database connections require access sessions; principal credentials authenticate only to management. Revocation, expiry, principal disablement and standing-principal removal cancel active work and stop result release. PostgreSQL closes affected connections with NY011; NY012 means a forwarded write has an unknown outcome and must not be replayed without reconciliation. Renewal and credential rotation preserve scope but cannot extend absolute lifetime. A replacement session needs fresh tokens.

Tokens remain stable across reconnects and restarts only within the same stored scope, route and root-key continuity. They must not be carried between scopes or routes. See access sessions.

Outside the Kubernetes peer topology, store state_dir on local disk with one owning service. Network storage is unsupported. The management Unix socket is unavailable on Windows; use the management TCP listener with configured administrator credentials. See operations.

SQL coverage

COALESCE on blind columns requires bare columns that share a domain and column type. Cross-domain or plain arguments are refused. In native GoogleSQL, ARRAY_AGG and STRING_AGG accept ORDER BY on plain keys. Blind or masked ordering keys and aggregate LIMIT remain refused. THEN RETURN on INSERT, UPDATE and DELETE follows the output policy for plain, blind and masked columns. Its WITH ACTION modifier remains unsupported.

Unknown SQL, functions, operators and protocol features fail closed. The allowlists are deliberate: an allowed function name does not allow transforming blind input. A small exact allowlist supports pgJDBC/HikariCP session-metadata statements, including transaction isolation and current schema/catalog queries; it is not general catalog access. See driver compatibility.

Policy and JSON boundaries

Tightening a revision fences result release for every open statement on the route, including statements whose columns were not changed. Multi-replica serving is supported only with the one-node, shared ReadWriteOnce PVC peer topology described in operations; it provides process failover, without node high availability.

JSON extraction operators are supported in direct top-level SELECT outputs and WHERE/JOIN predicates. GROUP BY, ORDER BY and DISTINCT require an exact Show rule for the extracted leaf. Blind, masked, unlisted and subtree extractions in those clauses are refused with NY005. Non-text blind JSON leaves cannot be used in predicates (NY005). R1 whitespace-prefixed PostgreSQL path elements and R3 digit-only GoogleSQL key steps are refused; see the matrix.

F5 remains a limitation for textual PostgreSQL json: whole-document reads reject duplicate protected keys, while extraction uses the member PostgreSQL selects. This difference is documented, not fixed; jsonb does not retain duplicate object keys. Avoid duplicate keys in textual JSON.
