SQL support

Nunya analyses PostgreSQL syntax against a schema snapshot and checks information flow before forwarding. An accepted SQL shape still has to satisfy the policy for every column it uses.

Statements and query shapes

The PostgreSQL route lowers SELECT, INSERT, UPDATE and DELETE, plus the transaction forms below. SELECT supports aliases, stars, joins, non-recursive SELECT CTEs, derived queries, supported subqueries, grouping, HAVING, ordering and limits. UNION, INTERSECT and EXCEPT retain provenance: blind outputs must stay in the same domain. INSERT supports VALUES and SELECT sources, explicit column lists, and analysed ON CONFLICT targets and assignments. UPDATE FROM, DELETE USING and supported RETURNING projections are analysed too. These are bounded parser paths, not a promise of arbitrary PostgreSQL compatibility.

SELECT INTO and data-modifying CTEs are refused. Recursive CTEs, windows, unrecognised expression nodes, unknown routines and unsupported query decorations fail closed. DDL, COPY, CALL, DO, SQL PREPARE/EXECUTE and other unrecognised statement kinds are refused with NY006. Unsupported syntax that cannot be fully analysed yields NY004. Wire-level prepared statements are supported separately.

A small exact allowlist of pgJDBC/HikariCP session-metadata statements is also accepted, including SHOW TRANSACTION ISOLATION LEVEL and current schema/catalog queries. Other SHOW forms and decorated variants fail closed; see pools and session metadata for the complete allowlist.

What a blind column permits

UseRule
Projection / RETURNINGA direct blind value becomes a token.
EqualityA bare blind column may use = in WHERE, JOIN ON or HAVING against a token parameter/literal, or another blind column in the same domain. Supported IN lists use equality against literal/parameter counterparts.
Grouping and countingGROUP BY, COUNT(column), COUNT(DISTINCT column), and NULL tests are permitted in their analysed contexts. Counts and equality relationships remain visible.
WritesA blind target accepts a matching-domain token, a direct same-domain blind column, or NULL. Plain/computed values cannot be silently promoted to blind data.
Other operationsOrdering, range comparisons, pattern matching, casts, transformations and non-count aggregates on blind input are refused.
SELECT c.id FROM customers c JOIN outbox o ON c.email = o.to_address;
SELECT email, count(*) FROM customers GROUP BY email;
INSERT INTO outbox (to_address, template)
SELECT email, 'reminder' FROM customers WHERE failed_payments >= 2;

Writing a blind value into a different domain or a plain target gives NY001. LIKE on a blind email gives NY002. Masked columns may be projected or returned; using one in an expression, predicate or join gives NY005. A parameter consumed as a blind counterpart cannot also be used as a plain expression in the same statement.

Closed operator allowlist

The following PostgreSQL operator names are recognised by the analyser. This is the syntax allowlist, not permission to apply every operator to blind input. A matching user-defined routine/operator name in the snapshot disables acceptance. Pattern spellings below include PostgreSQL's internal forms for LIKE/ILIKE and regular-expression operators.

= <> != < > <= >= + - * / % ^ || ~~ ~~* !~~ !~~* ~ ~* !~ !~*

BETWEEN, NOT BETWEEN, BETWEEN SYMMETRIC and NOT BETWEEN SYMMETRIC are analysed through their comparison operators. Equality is the permitted blind comparison; inequalities and patterns remain refused. Boolean logic and NULL tests are handled as explicit AST forms.

Paths must be literals. Extractions are accepted only as direct top-level SELECT items or WHERE/JOIN predicates of SELECT statements. PostgreSQL supports json and jsonb; GoogleSQL uses JSON_VALUE for scalar text and JSON_QUERY for JSON results. JSON_QUERY in a predicate is refused (NY005).

A Show leaf returns its value only after a runtime type check. A Blind leaf returns the same token as that position in a whole-document read. In Tokenize mode, masked or unknown paths return SQL NULL. A parent object is filtered like a whole-document read. In Show mode, unrelated new keys remain visible.

Predicates are type-guarded: a Show scalar changed into an object yields NULL and cannot match the object's text. Non-Text blind leaves are refused in predicates (NY005). Index steps are guarded by a container-type check, so an object member named "0" is never read as an array element.

For textual json (not jsonb), a whole-document read containing a duplicate protected key is refused. An extraction acts on the member PostgreSQL itself picks.

Closed function allowlist

Recognised aggregate names:

count sum avg min max bool_and bool_or every string_agg array_agg

Recognised scalar function names:

lower upper length char_length character_length octet_length substr substring left right trim btrim ltrim rtrim lpad rpad replace concat concat_ws position strpos split_part starts_with abs ceil ceiling floor round trunc mod power sqrt greatest least coalesce nullif now current_date current_timestamp date_trunc date_part extract age make_date to_char to_date to_timestamp md5 encode decode gen_random_uuid

Calls must be unqualified or qualified by pg_catalog. Names conflicting with user routines in the snapshot are refused. Aggregate ORDER BY, FILTER, OVER, WITHIN GROUP and variadic call decorations are not accepted. COUNT(*) is handled explicitly. On blind input, only the dedicated COUNT and COUNT DISTINCT paths are permitted: LOWER(email), MIN(email), MD5(email) and similar transformations are refused even though the function name is recognised for plain data. CASE, COALESCE, row, array and supported SQL current-time forms have their own provenance-aware AST handling.

Harmless local SET allowlist

These SET statements are acknowledged locally with a SET command tag; they do not change upstream settings or ParameterStatus. Other values and settings, RESET and SET DEFAULT are refused. Case and surrounding whitespace are normalised for the fixed string choices.

SettingAccepted value
extra_float_digits3 (integer or string)
application_nameOne string, at most 64 bytes
client_encodingutf8, utf-8, unicode
timezoneutc, etc/utc
datestyleiso or iso, mdy (one string or ISO and MDY as two arguments)
intervalstylepostgres
standard_conforming_stringson
SET application_name = 'agent';
SET client_encoding = 'UTF8';
SET TIME ZONE 'UTC';

A simple-query message containing only these no-op SETs is accepted. Mixing any with other statements in the same message yields NY006. Send them in separate requests. SET TRANSACTION is a distinct forwarded transaction path: isolation may be serializable, repeatable read, read committed or read uncommitted; read-only/read-write options are accepted. Unsupported transaction options fail closed.

Transactions and recovery

BEGIN / START TRANSACTION, COMMIT, ROLLBACK, SAVEPOINT, RELEASE SAVEPOINT and ROLLBACK TO SAVEPOINT are recognised. Statements inside transactions receive the same policy checks as standalone statements. A refusal in a transaction marks the session aborted; subsequent non-recovery statements receive SQLSTATE 25P02. Recover with rollback or rollback to a savepoint. COMMIT of an aborted transaction is converted to ROLLBACK. Two-phase transaction forms are refused.

BEGIN;
SAVEPOINT before_work;
SELECT id, email FROM customers WHERE failed_payments >= 2;
ROLLBACK TO SAVEPOINT before_work;
COMMIT;

Extended query protocol

Parse, Bind, Describe, Execute, Close, Flush and Sync are handled with ordered responses, named statements/portals and supported text/binary codecs. Parse must contain exactly one statement. Parameter formats, counts, declared types and result formats are checked. Token parameters are decoded only for approved blind counterparts. Tokens in other recognised text parameters are refused; see the binary detection gap. Prepared statements capture their policy and rewrite plan at preparation time; do not assume a reload rewrites already prepared plans.

After an extended-protocol error, messages are skipped until Sync and transaction recovery follows the gateway's aborted-session rules. Portal suspension is supported and logs the rows released in that execution. Unsupported protocol messages use NY010. Ordinary forwarded PostgreSQL statements emit an initial intent record and a completion record; do not count log lines as query executions.

Explicit tokenize-from-plain

A standalone table-free SELECT may call nunya_tokenize or nunya.nunya_tokenize with a literal domain name and one string literal or query parameter. It cannot be combined with FROM, WHERE, grouping, sorting, limits or another projection. The domain must enable tokenize and have a usable declared blind column type. Persisted per-session and per-principal domain limits apply. Reconnects do not reset the session count, and new sessions do not reset the principal window; exhaustion is NY007. This is an explicit permission to supply plaintext, not a way to read hidden database values.

SELECT nunya_tokenize('email', $1);

Use a bound parameter for the plaintext. Explicit tokenize arguments are redacted before read-log statements and fingerprints are produced.
