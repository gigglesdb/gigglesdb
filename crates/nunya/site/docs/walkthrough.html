01. Read customers who missed payments

The agent reads the rows it needs to act on.

SELECT id, email, phone, country FROM customers WHERE failed_payments >= 2 ORDER BY id

Direct to database

idemailphonecountry
3carol@example.test555-0103US
5eve@example.test555-0105GB

Through Nunya

idemailphonecountry
3tok_email_yspjixkfiwgm…[hidden]US
5tok_email_kvxekcyij7sr…[hidden]GB

The policy blinds email, masks phone and leaves id, country and failed_payments plain. The agent can select the customers needing attention without seeing contact details.

The bound token belongs to the same domain as outbox.to_address. Nunya decodes it for this approved write. The stored-values query is an operator-side view, not the agent view.

The database still holds the real address. Reading the blind column through Nunya returns the same token in this task scope.

06. Probe the email with LIKE

Pattern matching would reveal the value character by character.

SELECT id, email FROM customers WHERE email LIKE 'a%'

Direct to database

idemail
1alice@example.test

Through Nunya

REFUSED

NY002 · operation not allowed on a blind column

LIKE could reveal information about a hidden address. Nunya refuses this operation even though the underlying database accepts it.

07. Ordinary analytics on plain columns

08. Read a masked column

The placeholder hides the phone number without providing a reusable handle that can recover it.
