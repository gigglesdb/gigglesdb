A DATABASE GATEWAY FOR AI AGENTS

Let AI agents work with your database without seeing the data.

Nunya is a separate entry point for AI agents; your applications keep their direct database connection. Protected values become tokens, and Nunya checks where those tokens can go.

THE PROBLEM

SQL access should not mean
PII in the prompt.

An agent can queue a reminder without learning the customer's email address.

Give an agent ordinary database access and it can read contact details, paste them into free text, or follow a prompt injection asking it to exfiltrate them. Nunya checks the boundary between the agent and protected values.

The name means “none of your business”. The useful work still is.

WHERE IT FITS

Your app keeps its connection.
Agents get their own lane.

Nunya is not a proxy in front of your application.

Your services keep talking to the database exactly as they do today, with the same connection string and the same drivers. Nunya is a second entry point that you add for AI agents only.

Agents connect to Nunya with per-task credentials, using ordinary PostgreSQL drivers. Nunya connects upstream with its own least-privilege database role, configured by [upstream] user. Agents never get a route to the database itself.

THE REQUEST PATH

Values stay behind.
Work moves forward.

  1. 01

    Mark the boundary

    Declare blind and masked columns. Group compatible blind columns into domains.

  2. 02

    Connect the agent

    The agent connects to Nunya. Nunya connects upstream with separate credentials.

  3. 03

    Check every use

    Parse, resolve and check the statement. Decode tokens only in approved input positions.

  4. 04

    Return useful handles

    Blind outputs become tokens. Masked outputs become placeholders. Unsafe requests are refused.

THE BOUNDARY HOLDS HERE

A token is not permission
to put a secret anywhere.

NY001 · token used outside its domain

Probe the email with LIKE

SELECT id, email FROM customers WHERE email LIKE 'a%'
REFUSED

NY002 · operation not allowed on a blind column

These are exact demo outputs. The notes write stores no row. The LIKE probe never receives the hidden address. Read the token-detection limitations for protocol edge cases.
