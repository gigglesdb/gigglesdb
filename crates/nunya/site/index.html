A DATABASE GATEWAY FOR AI AGENTS

Let AI agents work with your database without seeing the data.

Nunya is a separate entry point for AI agents; your applications keep their direct database connection. Protected values become tokens, and Nunya checks where those tokens can go.

THE PROBLEM

SQL access should not mean
PII in the prompt.

An agent can queue a reminder without learning the customer's email address.

Give an agent ordinary database access and it can read contact details, paste them into free text, or follow a prompt injection asking it to exfiltrate them. Nunya checks the boundary between the agent and protected values.

The name means “none of your business”. The useful work still is.

WHERE IT FITS

Your app keeps its connection.
Agents get their own lane.

Nunya is not a proxy in front of your application.

Your services keep talking to the database exactly as they do today, with the same connection string and the same drivers. Nunya is a second entry point that you add for AI agents only.

Agents connect to Nunya with access-session credentials. For PostgreSQL, Nunya connects upstream with its own least-privilege database role, configured by [upstream] user. Deploy it so the tool network reaches only Nunya; the database has no route from that network. Keep upstream credentials outside the tool environment.

THE REQUEST PATH

Values stay behind.
Work moves forward.

  1. 01

    Mark the boundary

    Declare blind and masked columns. Group compatible blind columns into domains.

  2. 02

    Connect the agent

    The agent connects to Nunya. Nunya connects upstream with separate credentials.

  3. 03

    Check every use

    Parse, resolve and check the statement. Decode tokens only in approved input positions.

  4. 04

    Return useful handles

    Blind outputs become tokens. Masked outputs become placeholders. Unsafe requests are refused.

ACCESS THAT LASTS

One access session.
Across connections.

Give an agent a durable access session for ongoing work.

Reconnects and connection pools keep the same token meaning. Gateway restarts do too, while the session is active and its durable state and root key are retained. Understand access sessions.

Renewal keeps idle access alive within the absolute expiry. Expiry and revocation end active work and close open PostgreSQL connections with NY011; native Spanner ends active RPCs. Renew and revoke access.

Per-session and per-principal tokenization limits persist across reconnects, credential rotation and restarts. See tokenization limits.

Launch the agent with nunya exec, or give its tool credentials with nunya session env. The tool gets session credentials only. It never holds the database password or the root key. Protect session credentials.

Principals authenticate to the management API over TLS. Operators can bootstrap through the protected Unix socket, which carries administrator authority. Set up management access.

OPERATE WITHOUT INTERRUPTING

Change the policy.
Keep the gateway running.

Reload config and policy without a restart: TLS certificate and key files, configured identities in [[standing]], max_connections, schemas and search_path. Check reloadable settings.

Removing a configured identity ends its sessions and closes its connections. Apply and verify a reload.

Each route can use its own policy file. File contents reload independently; changing the selected file paths requires a restart. Configure route policies.

CONNECT WHERE YOU WORK

PostgreSQL.
And two ways to Spanner.

Use your PostgreSQL driver

Connect with psycopg and psycopg-pool, or pgJDBC with HikariCP, Spring Boot's default pool. Pooled round trips, gateway restart recovery, revocation and expiry are exercised in the tested client workflows. Use the documented JDBC settings.

Choose the Spanner route

Use PostgreSQL through PGAdapter, or connect to native GoogleSQL gRPC. Native Spanner supports multiplexed sessions, exercised with Google's Go client library.

An unknown write or commit outcome is reported as NY012 and never replayed. Read the refused-commit and recovery rules before retrying.
